## Runner hardening (2026-10-02)

The build box is WSL2 Ubuntu 24.04 on the build PC. The self-hosted runner
`buildpc-wsl` runs the `build-verify` workflow there, and the repository is
public. Three ways existed for workflow code to leave the Linux user it runs
as. All three are now closed. The runner still runs as `lang`: the job writes
the build tree `lang` owns, so a second user would need write access to
exactly what it would be isolated from.

Every command went through the sshgate MCP server (one approval per command).
The ssh session lands in Windows PowerShell; WSL is entered with
`wsl -d Ubuntu-24.04 -u <user>`.

### Traps met

- **`.runner_migrated` counts as configured.** With only `.runner` and the
  credential files removed, `config.sh` refused: "Cannot configure the runner
  because it is already configured". Removing `.runner_migrated` fixed it.
- **`wsl --shutdown` also stops what keeps WSL alive.** A Windows scheduled
  task, `CamouWslKeepAlive` (`wsl.exe -d Ubuntu-24.04 -u lang -- sleep
  infinity`), holds the distro up. After the shutdown it was `Ready`, not
  running; once the last `wsl` call returned, WSL stopped, the runner went
  offline, and the dispatched run sat queued for ten minutes.
  `Start-ScheduledTask -TaskName CamouWslKeepAlive` brought it back. Any
  procedure that runs `wsl --shutdown` must start that task afterwards.
- **`\\wsl.localhost\…` is not reachable from the ssh session** ("The
  specified network name is no longer available"). Stream a file in through
  stdin instead.
- **The ssh shell is Windows PowerShell 5.** `&&` is not a statement
  separator, and `$?` or `$(…)` inside double quotes is expanded by
  PowerShell before bash sees it. Scripts were passed base64-encoded.

is fully stable on 2026-10-06 and 156 arrives 2026-10-20, so the next re-pin is
due **by 2026-10-20** to keep "never more than one milestone behind".

#### The host oracle's 32 moved leaves

Read before accepting, as the plan requires. Explained by the re-pin:

- version strings: `ua`, `nav.appVersion`, `uad*.brands`, `fullVersionList`,
  `uaFullVersion` — 153 → 154, and the GREASE brand changed from
  `"Not_A Brand";v="8"` to `"Not A(Brand";v="99"`.
- `windowKeys`/`windowNames`: `+requestResize`.
- `protoCounts`: `Document` 251 → 250, `Window` 1233 → 1234, `cssProps`
  747 → 748.
- `err.stack`, `navConnection.rtt/downlink`: per-run paths and network noise;
  both are shape-only in the verify.

**Not explained by the re-pin**, and recorded as findings rather than waved
through:

- `codecs."video/mp4; codecs=\"hev1.1.6.L93.B0\""`: host `["probably", true]`
  (it was `["", false]` at 153). The host's Chrome decodes HEVC through the OS;
  the Linux build has no HEVC decoder, so the fork answers `""`. A
  Windows-claiming browser that cannot play HEVC is a tell → backlog.
- `gpu` (WebGPU): the host now returns an Intel adapter where the 153 capture
  had `null`. The box has no GPU and this verify drives the fork with
  `--use-angle=swiftshader`, so `requestAdapter()` resolves to `null` and the
  whole subtree is absent → backlog, and excluded by prefix meanwhile.
- `voices`: 3 → 22 (the host gained Google's online voices). Shape-only in the
  verify, so it changes nothing.

Both exclusions are in `verify_host_oracle.py` with the reason in the code and
a named backlog entry; `KNOWN_PREFIX` is new and exists only for `gpu`, whose
leaf set depends on the machine.

**A review of this branch caught the first version of that exclusion
measuring nothing**, and it is the clearest example of this project's dominant
failure mode in the whole re-pin, so it is recorded rather than quietly fixed.
The exclusion's own comment justified it by a property of the *machine* — "the
box has no GPU, so `requestAdapter()` resolves to null and the subtree is
absent" — but the code matched on **key name alone**. Consequences, none of
which today's run would have revealed:

- On the Windows build box of roadmap step 1, or for anyone who drops
  `--use-angle=swiftshader` from the probe argv, `requestAdapter()` returns a
  real adapter. `gpu.info.*` and `gpu.limits.*` would then be the host
  machine's real GPU reported under a spoofed Windows identity — exactly the
  cross-profile tell backlog item 2 exists for — and O1 would still print
  `0 DIFF … PASS`. The check would have been structurally incapable of seeing
  the thing it was pointed at, on the first machine where it could.
- Three capability integers (`gpu.limits.maxTextureDimension2D`,
  `maxComputeWorkgroupSizeX`, `maxBindGroups`) were compared **exactly** before
  the exclusion and were silently dropped by it. They are not "adapter
  strings", which is all the stated reason covered.

The fix is to test what the comment says: each `KNOWN_PREFIX` entry now carries
a predicate on the fork's own report (`lambda fork: fork.get("gpu") is None`),
evaluated **once per run** before the comparison loop — a per-leaf
"is one side absent?" test cannot do it, because for the fork's bare `gpu` key
the fork value is `None` while the host has no such leaf, so that one row would
escape the exclusion and print as a DIFF. When the predicate does not hold, the
whole subtree is compared again and the run says so (`note: prefix exclusion
'gpu' NOT in effect this run`).

The comparison moved out of `main()` into `compare(base, fork)` so it can be
tested without a browser, and `scripts/test_verify_host_oracle.py` is new:
four cases, including the RED one — a fork reporting a *different* adapter must
produce a DIFF. Made to fail on purpose by restoring the unconditional
predicate: `test_a_real_adapter_is_compared_again` fails and the three `gpu.*`
lines reappear as "known:". With the predicate: 4 passed, and the full
`checks` pytest line is 82 passed. The script is added to that line, so CI runs
it.

After the fix, on the box: rc 0, **0 DIFF, 239 same leaves, O1–O4 PASS**, and
no "not in effect" note — the predicate holds there, as the reason says.

## Recovery drill (2026-10-02)

Proves the claim the repo rests on: the box branch can be rebuilt from the
change set alone, and a failed rebuild leaves nothing behind.

camoucrome/drill`, run against the re-pinned repo and the re-pinned checkout:

The commit counts differ by design: the rebuilt branch has one commit per
patch, the real branch also carries five commits that touch only

identical, which is the property that matters — `difflines=0` means the
repository reproduces exactly what was built and verified.

The fixed script had to be put on the box first: the box's repo copy came from
`main`, which still has the pre-step-0 version. Transferring it through sshgate
needed the chunk-and-check discipline from the baseline transfer (five chunks,
one file each, sha256 per chunk — chunk 4 arrived corrupted and was resent in
halves). Both the gzip and the decoded script matched the Mac's hashes.
